# opencode-team-share

会话交接工具：把一条 opencode 会话导出成单个文件，交给同事导入后继续做。

- **不是 opencode 插件**：不注册 `opencode.jsonc`、不打 bundle；由启动器「团队协作」入口调用，也可以直接在命令行用
- **不依赖 git、不联网**：交接文件由同事自行传递（微信 / 邮件 / U 盘）
- **不加密**：文件是 gzip 压缩的 JSON，明文，便于排查；传递渠道请自行把握
- **零第三方依赖**：只用 `bun:sqlite` 与 node 内置模块，随安装包的 bun 直接跑 TypeScript

## 使用

### 交出方

启动器 → 左侧「协作 → 团队协作」→「导出会话」：

1. 搜索 / 选中一条会话
2. 填一句交接说明（可留空）
3. 点「导出…」，选保存位置（默认桌面，文件名 `会话交接-<标题>-<日期>.ocsave`）
4. 把文件发给同事

### 接手方

启动器 →「团队协作」→「导入会话」：

1. 点「选择文件…」选对方给的 `.ocsave`
2. 核对交接单（来自谁、什么会话、多少条消息、说明）
3. 选「导入方式」：
   - **接手继续**（默认）：同一会话，保留原会话 ID 与工作流阶段进度；此后在这个会话里的活动记入你的统计
   - **仅参考**：复制成新会话（`[参考]` 前缀），不带阶段进度、不沿用原会话成本与 Token；不会与发送方共享会话 ID。之后仍可在这个副本里接着做——「会话管理」会在首次对话时为它建一个全新工作流
4. 选「导入到项目」（下拉来自本机 `project` 表）
5. 点「导入」→ 成功后可直接点「打开这条会话」继续

稍后也可以手动打开：启动器选该项目目录 → 打开数字程序员 → 按 `Ctrl+X` 再按 `L` 打开会话列表 → 选标题带「[交接]」的那条。

## 命令行

```bash
bun run cli.ts list-sessions [--search 关键词] [--db <库>]
bun run cli.ts list-projects [--db <库>]
bun run cli.ts inspect --file <交接文件>
bun run cli.ts export --session <会话id> --out <文件> [--note 说明] [--db <库>]
bun run cli.ts import --file <交接文件> --project <projectId> [--db <库>]
```

stdout 输出 JSON，stderr 输出中文错误；退出码 `0` 成功 / `1` 失败 / `2` 参数错。

## 实现要点

| 主题 | 做法 |
|---|---|
| 数据库定位 | `--db` → `OPENCODE_DB` → `opencode.db`（发布通道）→ 其它 `opencode*.db` 按最近修改兜底；只读探测，避免打开动作影响选择 |
| 读会话 | `session` / `message` / `part` 三表，口径对齐上游 `opencode import` |
| 写会话 | 单事务；`project_id` 取本机项目，`directory`/`path` 用本机值；已存在则更新标题与时间；消息/part 按 id upsert |
| 写前备份 | 同目录 `opencode.db.bak-<时间戳>` |
| 路径归一化 | 导出时把工作区根/会话目录换成占位符，导入时还原成本机路径；长度 < 4 的替换目标跳过（避免把 `/` 当根替换） |
| 标题前缀 | 导入后加 `[交接] `，幂等（重复导入不叠加） |
| 工作流状态 | 一并交接：导出时用随包分发的 `opencode-sm-bundle` 里的 `Store` 读 `<项目>/.opencode/session-mgmt.db`，导入时用同一个 Store 写回目标项目（库不存在会自动建库并迁移）；bundle 缺失时自动跳过，只交接对话内容 |
| 两种导入模式 | `handoff`（默认）保留原会话 ID 并写回工作流状态；`reference` 生成新的 session/msg/part ID、清 `parentID`、标题加 `[参考]`、成本与 Token 归零、不写工作流状态。目的是避免收集端按 `sessionID` upsert 时把发送方的工作量改写成本机归属 |
| 并发保护 | opencode 正在运行时拒绝导入（启动器用 `tasklist` 检测） |

## 已知限制

- **文件是明文**：含完整会话正文、代码与路径。传递渠道与留存请自行把握。
- **工作流状态依赖会话管理组件**：状态搬运走 `runtime/opencode-sm-bundle` 里的 `Store`。该 bundle 随安装包分发；若手工部署时缺失，导入会跳过状态搬运（`workflowApplied=false`），接手后状态条为「未启动」，需重新说明进度或重新启动工作流。
- **工作流状态是整体替换**：重复导入会用文件里的快照覆盖目标端该会话的状态（交接语义是快照）。
- **导入需要目标项目已存在**：`session.project_id` 有外键，必须先在本机用该项目打开过一次 opencode。
- **仅参考副本是独立会话**：新 ID、无阶段进度、成本与 Token 从 0 开始；它不会与发送方的原会话互相同步。副本里要继续走工作流时，由「会话管理」自动建新状态（不会继承发送方已完成的阶段）。
- **交接是快照**：导出后双方各自的修改不会自动回流；要同步就再导出一次。
- **大会话文件较大**：全量消息 + part，长会话可达上百 MB（gzip 后）。
