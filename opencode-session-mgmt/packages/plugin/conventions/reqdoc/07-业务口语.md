# 业务口语规约

## 1. 与业务对话时禁用技术术语

与业务人员对话时，不得出现以下内部术语，必须使用右侧业务语言替代：

### 工具与操作

| 内部术语 | 业务语言 |
|---|---|
| reqdoc_scan | 扫描材料 |
| reqdoc_ingest | 录入需求 |
| reqdoc_answer | 回答追问 |
| reqdoc_memory_recall | 召回历史记忆 |
| reqdoc_assemble | 组装需求书 |
| reqdoc_confirm_features | 确认功能点 |
| reqdoc_init | 初始化目录 |
| reqdoc_import | 导入已有需求书 |
| reqdoc_adopt_baseline | 沿用已有需求书里已经写好的内容 |
| reqdoc_scope | 记录这次要改的范围 |
| reqdoc_export | 导出文档 |
| reqdoc_review_conventions | 规约检查 |
| workflow_advance | 进入下一阶段 |
| workflow_baseline | 建立基线 |
| workflow_revisit | 重新审视 |
| review_submit | 提交确认 |
| comprehension_add | 添加要点 |
| comprehension_ask | 追问要点 |
| comprehension_confirm | 确认要点 |

### 流程与状态

| 内部术语 | 业务语言 |
|---|---|
| 开放项 | 待确认事项 |
| 槽位 | 需求要点 |
| 组装 | 生成需求书 |
| 定稿 | 最终确认 |
| 门禁 | 检查关卡 |
| in_progress | 进行中 |
| approved | 已通过 |
| not_started | 未开始 |
| edge | 边界与异常 |
| prd | 需求规格书 |
| L1 记忆 / 记忆免问 | 历史记忆 / 已采信历史记忆 |
| L2 组织知识 | 共享知识 |
| draft | 待确认 |
| 必填容器覆盖 | 术语与字段章节是否齐 |
| 进 prd 被拦 | 还进不了需求规格书阶段 |
| 落定 | 确认入库 |
| 承认基线 | 沿用旧稿已写好的内容 |
| 本次增量范围 | 这次要改的部分 |

### 技术缩写

| 内部术语 | 业务语言 |
|---|---|
| RBAC | 权限控制 |
| MTTR | 故障恢复时间 |
| RTO/RPO | 恢复时间目标/恢复点目标 |
| UAT | 用户验收测试 |
| API | 接口 |
| NFR | 非功能需求 |

### 定稿清单

定稿时须逐项确认四项（对应 `review_submit` 的清单，四项全真才通过）：

| 内部术语 | 业务语言 |
|---|---|
| completeness | 信息完整（背景/口径/字段齐全） |
| clarity | 表达明确（无歧义、可落地） |
| edgeCoverage | 边界覆盖（异常/权限/合规场景俱到） |
| resolution | 职责清晰（技术初步可行性已确认） |

## 2. 来源标注保留

`[文档]`、`[问答]`、`[缺省]` 为来源标注，业务可理解，保留使用。但向业务解释时应说"这份来源是文档/问答/暂未获得"，不解释为"内部标签"。

## 3. 状态条与内部状态的转述

状态条只进系统提示、**面向模型**（业务在界面上看不到），因此允许携带操作信息——地址（"必填容器未覆盖：4.1、5.1.2.1"）、覆盖率、门禁原因等；这些是模型行动的依据，**不要为了"说人话"删掉或改写状态条**。

**但凡讲给业务听的**（对话里复述进度、解释为什么卡住、引用状态条原文），一律先按第 1 节翻译成业务语言：

| 状态条原文（给模型） | 对业务怎么说 |
|---|---|
| 知识库：必填槽位 23/31（74%）；未就绪：必填容器未覆盖：4.1 | 信息完整度 74%，还差"术语"那一章（不说"槽位""容器未覆盖"） |
| 已采信历史记忆 1 项待你落定（不必再问）：4.1.CLD | 有个术语按你之前说的先定了，不用再问你（不说"L1 记忆免问，待你用 reqdoc_answer 落定"） |
| 提交状态：blocked（未完成：prd、review） | 现在还进不了后面两个阶段（不说"blocked"） |
| 已确认 3/7 项，还有 4 项待你确认 | 直接照说（本来就是业务语言） |

## 4. 禁止出现的句式

- "请调用 reqdoc_xxx 工具" → "我来帮你扫描/校验/..."
- "workflow_advance 进入 prd" → "现在可以进入需求规格书阶段"
- "reqdoc_r10 规定" → 直接说要求，不引用规则编号
- "P0.1 前置条件" → "在进入下一步之前，需要先..."
- "completeness 不达标" → "信息还不完整，需要补充"
