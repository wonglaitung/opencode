# 业务口语规约

## 1. 与业务对话时禁用技术术语

与业务人员对话时，不得出现以下内部术语，必须使用右侧业务语言替代：

### 工具与操作

| 内部术语 | 业务语言 |
|---|---|
| reqdoc_scan | 扫描材料 |
| reqdoc_probe | 记录覆盖情况 |
| reqdoc_score | 质量打分 |
| reqdoc_check | 文档校验 |
| reqdoc_field_dict | 字段定义 |
| reqdoc_confirm_features | 确认功能点 |
| reqdoc_init | 初始化目录 |
| reqdoc_import | 导入初稿 |
| reqdoc_export | 导出文档 |
| reqdoc_review_conventions | 规约检查 |
| workflow_advance | 进入下一阶段 |
| workflow_revisit | 重新审视 |
| review_submit | 提交确认 |
| comprehension_add | 添加要点 |
| comprehension_confirm | 确认要点 |

### 流程与状态

| 内部术语 | 业务语言 |
|---|---|
| 探针 | 覆盖项 |
| 渲染 | 生成文档 |
| 定稿 | 最终确认 |
| 打分卡 | 质量评分 |
| 门禁 | 检查关卡 |
| in_progress | 进行中 |
| approved | 已通过 |
| not_started | 未开始 |
| edge | 边界与异常 |
| prd | 需求规格书 |

### 技术缩写

| 内部术语 | 业务语言 |
|---|---|
| RBAC | 权限控制 |
| MTTR | 故障恢复时间 |
| RTO/RPO | 恢复时间目标/恢复点目标 |
| UAT | 用户验收测试 |
| API | 接口 |
| NFR | 非功能需求 |

### 打分维度

| 内部术语 | 业务语言 |
|---|---|
| businessValue | 业务目标与价值 |
| flowClosure | 主流程闭环 |
| edgeControl | 异常与边界控制 |
| compliance | 合规与数据安全 |
| authority | 权限与机构隔离 |
| material | 素材真实性 |
| nfr | 非功能覆盖 |
| acceptability | 可验收性 |

## 2. 来源标注保留

`[文档]`、`[问答]`、`[缺省]` 为来源标注，业务可理解，保留使用。但向业务解释时应说"这份来源是文档/问答/暂未获得"，不解释为"内部标签"。

## 3. 状态条显示

状态条中的技术信息（探针覆盖、渲染校验、打分维度）一律用业务语言展示，如：
- "信息覆盖：已确认 3/7 项"（不说"探针覆盖：已问 3/7 探针"）
- "文档校验：通过"（不说"渲染校验：✓ 结构合规"）
- "质量评分：85/100，达标"（不说"PRD 评分：85/100"）

## 4. 禁止出现的句式

- "请调用 reqdoc_xxx 工具" → "我来帮你扫描/校验/..."
- "workflow_advance 进入 prd" → "现在可以进入需求规格书阶段"
- "reqdoc_r10 规定" → 直接说要求，不引用规则编号
- "P0.1 前置条件" → "在进入下一步之前，需要先..."
- "material 维度扣分" → "素材支撑不足，需要补充"
