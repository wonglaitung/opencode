# sdlc 静态扫瞄质量门禁（SonarQube 对齐）

对齐 SonarQube 质量门禁，AI 编写/修改代码时主动满足，降低提交后被扫瞄拦截的概率。

## 1. 复杂度与代码异味
- 单函数认知复杂度 ≤ 15；超出用卫语句或拆分降嵌套。
- 方法/函数行数受控（建议 ≤ 60），大类按职责拆分。
- 不写空 catch / 吞异常；catch 须处理或显式上抛。

## 2. JS/TS 类型与异步写法
- 禁用 `any` / 隐式 any；确需动态类型用具体联合类型或泛型。
- 深层嵌套回调改用 async/await，避免回调地狱。

## 3. 可靠性 Bug 防护
- 取值先做 null / undefined 守卫，防 NPE / 空引用（Java Optional、JS 可选链与显式判空）。
- 公开方法补边界与异常分支单测（Java JUnit5、JS Vitest/Jest），覆盖主路径与错误路径；单测不得依赖外网资源，外部调用一律 mock。

## 4. Sonar 特有动作
- SQL 一律参数化（Java PreparedStatement / ORM 绑定、JS 参数化查询），禁字符串拼接。
- Java 强制 try-with-resources、JS 用 `using` / finally，禁裸 `close()` 易漏路径。
