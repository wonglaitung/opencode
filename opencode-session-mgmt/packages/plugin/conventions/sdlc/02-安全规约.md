# sdlc 安全规约

## 1. 凭证与密钥

不硬编码密码/令牌/Key；经环境变量或密钥管理服务注入，不入库。

## 2. 输入校验与防注入

所有外部输入使用前校验；参数化防 SQL 注入、防命令/路径遍历，禁字符串拼接。对外发起的网络请求（URL / 重定向 / 文件读取）须校验目标归属与协议白名单，防 SSRF；不信任任何外部或反序列化输入，反序列化前校验类型与来源。

## 3. 最小权限

仅申请必要权限；文件/网络/DB 按最小集访问。

## 4. 依赖安全

仅用可信来源、锁版本、定期审计 CVE 并及时更新。

## 5. 输出编码

拼接到 HTML/日志/命令的输出做编码，防 XSS 与注入。

## 6. 密码学原语

不使用 MD5 / SHA1 / DES / ECB 等弱算法或弱模式；密钥由安全随机数生成并经密钥管理注入，不硬编码；优先采用标准库的安全默认值（如 GCM 而非 CBC、RSA 配 OAEP）。

## 7. 复杂度与代码异味

- 单函数认知复杂度 ≤ 15；超出用卫语句或拆分降嵌套。
- 方法/函数行数受控（建议 ≤ 60），大类按职责拆分。
- 不写空 catch / 吞异常；catch 须处理或显式上抛。

## 8. JS/TS 类型与异步写法

- 禁用 `any` / 隐式 any；确需动态类型用具体联合类型或泛型。
- 深层嵌套回调改用 async/await，避免回调地狱。

## 9. 可靠性 Bug 防护

- 取值先做 null / undefined 守卫，防 NPE / 空引用（Java Optional、JS 可选链与显式判空）。
- 公开方法补边界与异常分支单测（Java JUnit5、JS Vitest/Jest），覆盖主路径与错误路径；单测不得依赖外网资源，外部调用一律 mock。
