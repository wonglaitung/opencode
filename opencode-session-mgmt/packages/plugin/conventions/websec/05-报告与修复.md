# 报告与修复

- 报告结构：范围与边界、测试方法、发现清单、局限与未覆盖项、残余风险。
- 发现清单分两组：已确认（按严重度排序，每条带复核会话）与待验证（不评严重度）。
- 每条发现写清：端点、身份、证据 id、复现步骤、影响、修复建议；confirmed 另写复核会话 id。
- 报告写清测试模式（普通/越权）；越权 confirmed 必须同时引用 baseline 与 privileged 证据，普通测试 confirmed 必须有正文证据。
- confirmed 证据可来自 Edge、匿名探测、只读配置检查或显式写探测（fallback 除外）；manual/curl 证据只能标 suspected 或走 fallback。
- 报告前确认覆盖矩阵与历史回归已收口；未收口的项要么补测，要么写清 not_applicable 理由。
- 修复建议要可执行：具体到校验位置、权限判断、配置项或依赖升级，不给泛泛而谈的“加强安全”。
- 敏感信息脱敏：不贴真实用户数据、Cookie、令牌、内网地址；证据正文保留在本地。
- 报告必须写入项目内 `websec-evidence/<sessionID>/report.md`、`report.json` 与 `coverage-ledger.json`；完成时必须明确告知开发者这些文件的绝对路径。
- 无发现时 verdict=passed，并列出已检查项与局限，避免“没测”被误读为“安全”。
