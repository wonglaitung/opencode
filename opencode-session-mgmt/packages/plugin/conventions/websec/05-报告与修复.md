# 报告与修复

- 报告结构：范围与边界、测试方法、发现清单、局限与未覆盖项、残余风险。
- 每条发现写清：端点、身份、证据 id、复现步骤、影响、定级、修复建议。
- 报告写清测试模式（普通/越权）；越权 confirmed 必须同时引用 baseline 与 privileged 证据，普通测试 confirmed 必须有正文证据。
- 修复建议要可执行：具体到校验位置、权限判断、配置项或依赖升级，不给泛泛而谈的“加强安全”。
- 敏感信息脱敏：不贴真实用户数据、Cookie、令牌、内网地址；证据正文保留在本地。
- 无发现时 verdict=passed，并列出已检查项与局限，避免“没测”被误读为“安全”。
