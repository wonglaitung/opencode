# websec 测试纪律

- 只测试你负责或获准自测的目标：目标、环境、账号、时间窗、限速、停止条件必须记录在 scope 中。内部开发自测不需要工单/邮件/合同，但必须确认测试边界。
- 默认只读（GET/HEAD/OPTIONS）。写操作、删除、批量提交、爆破、越权写、上传利用须开发者逐次确认，未授权一律不做；写探测只用 `websec_write_probe`，单次 POST/PUT/PATCH，禁止 DELETE。
- 发现越界、真实数据影响、触发告警或可能影响可用性时立即停止并回报，不继续探测。
- 证据只存本地索引（URL/方法/身份/时间/哈希/本地路径）。不把请求/响应正文、Cookie、令牌或用户数据发到上游。
- 测试期间生成的所有内容（页面、接口、截图、证据、报告）必须放到项目目录 `websec-evidence/<sessionID>/`，禁止写 `%TEMP%` 或项目外路径。
- 没有请求/响应与复现步骤的结论只能标 suspected，不得标 confirmed；不把猜测写成漏洞。
- 每个入口的必检类别都要在 `websec_coverage` 收口；不适用也必须写理由。历史 finding 必须在 `websec_regression` 逐条回归。
- 报告中敏感字段脱敏；不导出真实用户数据，不保留生产口令。
