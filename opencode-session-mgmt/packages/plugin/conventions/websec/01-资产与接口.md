# 资产与接口枚举

- 必须接管已登录会话：启动 Edge，让用户在 Edge 中登录并走完页面/操作流程；不要用 curl 或源码静态检查替代用户走查。
- 每个入口记录：method、path、参数位置（query/body/header/path）、身份、触发方式、来源（edge/source/manual）；用 `websec_surface` 落库，Edge 证据用 `sync_edge=true`，源码路由/人工入口用 `entries`。
- 顺带记录技术栈指纹：响应头（`Server`、`X-Powered-By`、`X-AspNet-Version`）、静态资源路径与版本串（jQuery/Bootstrap/Vue/React/Spring Boot/Tomcat/nginx）、HTML 注释里的生成器标记；写入入口备注，作为后续「版本 → 已知问题」的输入，本阶段不下结论。
- 覆盖页面、XHR/fetch、表单、上传、导出、回调、调试端点；不越界爬取第三方域名。
- 新增入口会自动生成 9 个必检类别（authn/authz/input/cors/headers/options/export/debug/logic）；用 `websec_coverage` 标记 tested/finding/not_applicable，not_applicable 必须写理由。
- 进入本阶段前必须问「普通测试还是越权测试」并 `websec_edge_capture(start, mode=...)`；用户说「本次录入已完成」后 `capture`。普通测试单阶段，越权测试 baseline/privileged 两阶段。响应正文落项目内证据目录，对话只看摘要。
- 排除 logout、delete、付款、发信等破坏性或不可逆链接；只记录不触发。
- 所有页面、接口、证据正文和报告必须落在项目内 `websec-evidence/<sessionID>/`，禁止 `%TEMP%` 或项目外路径。
- 覆盖不到的模块与原因写入 limitations，同时把对应覆盖项标为 not_applicable 并写理由；两者口径保持一致。
