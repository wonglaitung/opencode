# 证据与定级

- 每个候选至少一对 baseline/proof：同身份、同端点、可控变量，记录请求/响应、时间与哈希。
- 复现失败或证据不足：降级为 suspected 或从报告中移除，不保留“可能”。
- confirmed 前必须独立复核：用 task 启动只读子代理并要求它「尝试推翻」，复核未被推翻才可确认，并记录 verifierSessionID；复核会话不能是当前会话。
- 只有 confirmed 才评严重度；suspected 不评严重度（避免用严重度给未证实结论背书）。
- 定级参考：critical=直接接管/大规模数据；high=稳定越权读写/敏感数据；medium=有限影响或需前置条件；low=信息泄露/加固缺失；info=提示。
- 写清影响与利用前提，不夸大；同一根因合并，不按端点堆数量。
- 确认误报后记录排除理由，供报告 limitations 使用。
