# 输入与配置检查

## 无害验证标记（只观察，不执行）
- 原则：标记不得执行脚本、不得读真实文件、不得联外网；只比较响应差异（反射、编码、报错、状态码、耗时）。
- XSS：用不执行的标记（`"><marker>`、`'><marker>`），只看是否原样反射与编码是否正确；禁止 `onerror=`、`onload=`、`javascript:` 等会执行或外联的载荷。
- SQL 注入：单引号/双引号/反斜杠，观察报错或 5xx；禁止 UNION、堆叠语句、`SLEEP`/`BENCHMARK` 等时间或批量载荷。
- 模板注入：`{{7*7}}`、`${7*7}`、`<%= 7*7 %>`，只查响应是否出现 `49`。
- 路径穿越：用不存在的标记文件名（如 `../../marker-nonexistent`），比较错误差异；不读取真实系统文件。
- 开放重定向：`//example.invalid`、`https://example.invalid`，只看 `Location` 是否指向外域；不跟随跳转。
- SSRF：只对 `localhost:<未监听端口>` 观察错误/耗时差异；不访问内网服务、不联外网。
- 命令注入：只观察报错/耗时差异，不执行任何命令、不写文件。

## 响应指示（命中只代表值得进一步验证）
- SQL 报错：`SQL syntax`、`SQLSTATE`、`ORA-`、`PostgreSQL`、`mysql_`、`Unclosed quotation`。
- 框架调试页：`Traceback (most recent call last)`、`Whitelabel Error Page`、`Whoops`、`Stack trace`、`at java.`、`DEBUG=True`。
- 默认/管理页：`Welcome to nginx`、`Apache2 ... Default Page`、`IIS Windows Server`、`Tomcat`、`Jenkins`、`Kibana`、`Index of /`。
- 调试/敏感端点：`/actuator`、`/swagger-ui`、`/.git/HEAD`、`/.env`、`/phpinfo.php`、`/console`、`/debug`。
- 指纹头：`X-Powered-By`、`Server`、`X-AspNet-Version`、`X-Debug-Token`。
- 命中后先登记证据，再决定标 tested/finding；不要把「默认页」「报错串」直接写成漏洞。

## 版本指纹（只能 suspected）
- 命中版本串（如 jQuery 1.x、Spring Boot 1.x、Struts 2.x、Log4j 1.x）时，登记证据并标 `suspected`，注明「版本可能对应已知问题，未验证利用」。
- 不得据此断言 CVE、不得直接定级；升级 `confirmed` 必须经独立复核并给出实际影响证据。

## 上传、配置与业务逻辑
- 上传：检查类型/后缀/内容校验与返回路径，不上传 webshell 或可执行内容。
- 配置：优先用 `websec_config_check(developer_confirmed=true)` 对同源入口做无 Cookie GET/OPTIONS，采集 CORS、安全响应头、Cookie 属性（只看属性，不存值）、TLS、目录列表、调试/actuator 端点；结果自动登记 cors/headers/options 覆盖。
- CORS 通配 `*`、反射 Origin、通配 + 允许凭据、缺失 CSP/X-Frame-Options/X-Content-Type-Options/Referrer-Policy 都要记录；确认后改为 finding。
- 业务逻辑：只验证可逆、低影响的分支（如价格/数量边界），不完成真实交易。
- 输入/导出/调试/逻辑类别也要逐入口收口；不适用时标 not_applicable 并写理由。
